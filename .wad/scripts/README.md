# scripts/ — WAD extractors

Standalone Python scripts that read a live source of truth (the build system,
CI config, git tags, a database, an API) and write WCL data files into
`../data/*/generated/` or `../data/generated/`. Run them all with
`just wad-extract` (repo root) or `uv run scripts/<name>.py` individually.
Current set: `extract_cargo.py` (crate dep relations + module graph),
`extract_ci.py` (workflow YAML → pipeline stages with step summaries),
`extract_http_api.py` (the serve endpoints), `extract_releases.py` (git tags
→ the Build & deploy releases table).

## The conventions (every extractor follows these)

1. **uv single-file scripts.** Shebang `#!/usr/bin/env -S uv run` plus a
   [PEP 723](https://peps.python.org/pep-0723/) inline-metadata header:

   ```python
   # /// script
   # requires-python = ">=3.11"
   # dependencies = ["pyyaml>=6"]
   # ///
   ```

   Self-contained on purpose: each script carries its own ~20-line WCL-emit
   helper rather than importing a shared module — copy it into new scripts.

2. **One script, one output file.** `extract_cargo.py` owns
   `data/generated/cargo.wcl` — nothing else writes it, and it writes nothing
   else. Re-running is always a **full overwrite**, never an append or merge.

3. **A generated banner, always first:**

   ```
   // GENERATED by scripts/extract_cargo.py — do not hand-edit; re-run `just wad-extract`.
   // Source: cargo metadata (workspace root)
   ```

4. **Deterministic output.** No timestamps; sort every collection. A re-run
   with an unchanged source must be byte-identical, so `git status` stays
   quiet and `wcl diff` (the spec workflow) sees only real changes.

5. **Stable ids derived from source names** (crate name → relation id, job
   key → stage id). Hand-authored data may *reference* generated ids but must
   never reuse them.

6. **Empty result still writes the file** (banner + `namespace` line), so the
   committed import line never dangles.

7. **Output must pass `wcl check`.** `just wad-extract` chains into
   `wad-check`; a broken emitter is a broken run.

8. **Generated files are committed.** The diff→spec workflow materialises old
   git revisions; uncommitted generated data would vanish from the old side
   of every diff.

## Writing a new extractor

Start from any script here (or `extract_repo.py` in a fresh `wcl init wad`
scaffold — the generic template). The shape is always:

1. locate the WAD root (`Path(__file__).resolve().parents[1]`) and the source
   of truth relative to it;
2. read the source (subprocess, file parse, DB query, HTTP call — uv deps
   make any of these one line of metadata);
3. map source records onto WAD block kinds (relations, pipelines, code_items,
   domain_objects, infra_nodes…), with a small in-script table for anything
   that needs human naming (e.g. crate → container id);
4. render WCL text with the emit helper and overwrite the output file.

A worked database example (SQLite → `code_item` with `db_table` children) is
sketched in the wad wskill's *write an extractor* procedure.
