# WCL — Claude Code Instructions

This file is a **navigation map**, not a spec. For depth, follow the pointers in
[Where the docs live](#where-the-docs-live) rather than expecting it all inline.

## Layout

- `crates/wcl_lang` — language library: lexer, parser, AST, document view, lazy evaluator, schema validator, host-binding API
- `crates/wcl` — `wcl` CLI binary (`parse`, `check`, `eval` / `get`, `set`, `fmt`, `diff`, `init`, `answer`, `repl`, `lsp`, `editor`, `wdoc build` / `serve` / `pdf` / `markdown` / `skill` / `comments`, `wskill check` / `install` / `graph` / `lint` / `audit` / `op`). The `wdoc serve` watch+axum dev server lives here (`src/serve.rs`), since it's CLI-only (the watcher accumulates changed paths but rebuilds only on an explicit trigger — stdin Enter or `POST /__wdoc_rebuild`). `init` (project scaffolding) lives in `src/scaffold/` and embeds its own small WCL stdlib (`lib/scaffold/*.wcl` → `schema_registry()`) plus built-in templates (`templates/*.wcl`); a template opts in with `import <scaffold.wcl>` and references answered properties via an `answer("name")` builtin. See the `wcl init` implementation contract below. `editor` (`src/editor/`) serves the browser editor for the current directory — see the editor entry below and the [`editor-ui/`](#layout) bullet.
- `crates/wcl_lsp` — `tower-lsp` language server driving `wcl lsp`
- `crates/wcl_wdoc` — library crate driving the `wcl wdoc` subcommands; renders pages to HTML/PDF/Markdown. Embeds its WCL stdlib (`lib/*.wcl`) into a `wcl_lang::Registry` via `build.rs` (`schema_registry()`); a document opts in with `import <wdoc.wcl>`. See the [wdoc feature map](#wcl_wdoc-feature-map).
- `crates/wcl_wskill` — library crate owning the **wskill model**: a wskill folder's typed unit graph (units, nested index trees, `related` + pin edges, per-unit block lists, each carrying the file + byte span it is written at, plus the `related_editable` computed-field flag and `Graph::unindexed()`) **and the two readings over it**: the lint rule engine (`lint::lint(&Graph) -> Vec<Finding>`, one pass, three severities, one finding shape — nomination is a severity, not a second command) and the range audit (`audit::Audit::across(entry, &Range)` — two graphs diffed into the union graph, before ∪ after with removals marked). Read from an entry document (`Graph::open`), an already-open one (`Graph::from_document`), or a git revision (`Graph::open_at_rev`, over `wcl_wdoc::git`). It also owns the wskill *format*: `ROOT_MARKER` (`wskill.wcl`), the `Registry` reading the `topic` + `artifact` projections — which is why `wcl_wdoc`'s sidecar lookup takes the marker filename as a parameter (`owner_root`) and names no format itself — and the **embedded WCL library** (`lib/*.wcl` → `schema_registry()` / `install_stdlib()`; see the wskill library contract below). Sits between `wcl_wdoc` and the binary because the model's consumers (`wcl wskill check` / `install` / `graph` / `lint` / `audit` / `op`, the curator agent, the editor's graph and audit views) must not need a running editor. Layout is NOT here — a graph view lays out what the model describes. Beside the model sits `ops` — the ONE vocabulary of structural edits (`pin_unit`/`unpin_unit`/`reorder_children`, the index tree's `create`/`delete`/`move`/`promote`/`demote`, `related_add`/`related_remove`), **id-addressed** by `(kind, id)` and returning `Change`s (file → new text) for the caller to commit, so a curator and an editing UI run the same functions. A kind the caller omits is **inferred when the id names exactly one node** (`Graph::nodes_named`) and refused when it names two — ids are unique across kinds by convention only, and an op landing on the wrong kind is the failure the addressing exists to prevent. The ops' **JSON dialect is the library's too** (`ops::from_json` / `to_json` / `is_op` / `OP_NAMES`, accepting the editor's older `index_id`-style spellings), so `POST /api/nav/op` decodes its wskill family through it rather than translating, and `wcl wskill op --dry-run` prints ops a host can send back verbatim. Where a host holds only a span (the editor drags an edge between rendered nodes) it resolves the span to a `NodeRef` (`ops::node_ref`) and calls the same `ops::edit_related`. What the crate deliberately does NOT own is **where a brand-new top-level block goes** — that is a host placement convention, so `Op::CreateIndex` names an `IndexHome` (`Under(index)`, which is a format fact, or `InFile(path)`, which is the host's placement answer) rather than choosing; `ops::index_block` + `ops::check_new_index_id` are public so a host creating the file itself still builds and validates the index the one way. Refusals are `Error::Op(String)` on the crate's one error type — an op message is written for the person who asked and a host shows it verbatim.
- `crates/wcl_lang/fuzz` — `cargo-fuzz` targets (`parse` / `eval` / `format_round_trip` / …); run via `just fuzz-run <target>` on nightly. See `crates/wcl_lang/fuzz/README.md`.
- `editor-ui/` — the `wcl editor` frontend: a SolidJS app on the Forge design system (`@forge/{ui,code,tokens}` consumed as git subdir deps from `github:wiltaylor/forge`), built with vite + pnpm. `crates/wcl/build.rs` rebuilds `editor-ui/dist` when the sources are newer (pnpm required; `WCL_EDITOR_UI_SKIP=1` embeds a placeholder instead) and `src/editor/assets.rs` embeds it via rust-embed (debug builds read the folder from disk — frontend iteration needs no cargo rebuild). Dev loop: `wcl editor` + `pnpm dev` (vite on :5174 proxying `/api`, incl. the LSP WebSocket). `pnpm-lock.yaml` is deliberately not committed (pnpm git-subdir-dep bug); bumping forge means updating the pinned codeload URLs in `package.json`'s `onlyBuiltDependencies`. **Verify a forge bump in CI, not just locally**: installing a git-subdir dep runs forge's own monorepo `prepare`, which builds every sibling package outside turbo's build ordering — a path forge's own CI doesn't exercise. Two 2026-07-28 bumps died there and passed locally first (`TS2305` from `@forge/chat` typechecking before `@forge/ui`'s `dist` existed; `TS2883` from declaration emit naming a type through pnpm's virtual store), so a green local `pnpm install` — even on a cold store — proves nothing. Since `build.rs` runs this install, a bad pin breaks `cargo build` itself. Forge `a1130465` added `isolatedDeclarations` to every package's `tsconfig.build.json`, which turns that whole class into a local compile error there; still confirm a bump in CI.
- `editors/vscode` — VS Code extension stub that spawns `wcl lsp` (`editors/vscode/README.md`)
- `editors/tree-sitter-wcl` — tree-sitter grammar stub (`editors/tree-sitter-wcl/README.md`)
- `examples/` — fixture files used by tests (incl. `imports/` for module loading, `errors/` for negative diagnostics)
- `docs/` — the user-facing documentation site, authored in WCL and built with `wcl wdoc`
- `.wad/` — the reference **WAD** (Wil's Architecture Document): a typed architecture data model of WCL itself (`wad.wcl` + `schema/` + per-view `data/` + `wdoc/book/` templates + `scripts/` extractors), rendered by `just wad-build` / `just wad-serve`. The canonical WAD schema is the `WAD_SCHEMA_BASE_WCL` heredoc in `crates/wcl/src/scaffold/templates/wad.wcl` (`just wad-schema-sync` / `wad-schema-check`, CI-gated); `wcl init wad` scaffolds new WADs (schema 0.6.0 makes `component.kind` the `ComponentKind` vocabulary — `:cli`/`:tui`/`:web_api`/`:ui` mark the editor's native content surfaces — over 0.5.0's `boundary` blocks + optional `boundary` on system/external_system, which the Systems view and the context diagram both read); `wcl wad spec --from <rev>` derives change-spec skeletons from a diff (`crates/wcl/src/wad.rs`). Extractors under `.wad/scripts/` (uv single-file Python) own `data/generated/` — committed, never hand-edited (`just wad-extract`). How-to lives in the `wad` wskill (`docs/wskills/wad/`) — one mode-routed lifecycle skill (`wad plan | issue | build | doc`) that also absorbed the former wplan/wissue/wbuild skills; the seven `.claude/agents/*.md` files are generated from its `agent` blocks via `just skills-install`.
- `README.md` — user-facing quickstart

## What's implemented

Capability summary per crate; the reference pages above carry the detail.

- **`wcl_lang`** — hand-written lexer + recursive-descent parser → `Source` AST + `SymbolIndex`; strings/heredocs with escapes + interpolation (`<<'TAG'` raw form is verbatim). `Document` view with lazy, cached field eval + cycle detection. Expression evaluator (literals, member access, calls, fn literals, let-bindings, block exprs, arithmetic/comparison/logic with numeric promotion, `??` none-coalescing, `try`/`catch`). `fn name(…)` items (indexed lets). Schema constraints: `type Name = TypeRef` aliases + `@min`/`@max`/`@non_empty`. Schema system (`@document`/`@block`/`@child`/`@children`/`@inline`/`@default`/`@table`/`@decorator`/`@contextual`/`@declares_kind`), type system (`type`/`interface`/`union`/`symbol_set`/`list`/`tensor`/`fn`/`&T` refs), host bindings (`Environment`, `from_fn`, `FromValue`/`IntoValue`), and builtins (collections / tensors / strings / lists / math / control flow). Imports: quoted disk + angle-bracket system via `Registry`. Edit path: `parse_for_edit` + AST mutation + `format::to_source`. JSON value serialization. → see the `wcl` wskill (`docs/wskills/wcl/`) and `cargo doc`.
- **`wcl` CLI** — `parse` / `check` / `eval`+`get` / `set` / `fmt` / `diff` (WCL-aware entity/field document diff over the *evaluated* views — emits a re-parseable WCL tree by default, `--format json` for the flat change array; either side may be a `<rev>:<path>` git specifier whose imports resolve from that revision, materialised via `git archive | tar` — see `src/gitspec.rs`) / `init` (scaffold a project folder from a WCL template — a built-in name, a user template under `$XDG_DATA_HOME/wcl/templates/<name>/template.wcl`, or a template `.wcl` path / folder; built-ins ⟶ user templates ⟶ disk-path precedence, all surfaced by `--list`; collects property answers from `-D key=value`, an `--answers` `.wcl`/`.json` file, an interactive prompt, or the property `default`, then writes the `file`/`folder` blocks to disk; see `src/scaffold/`) / `repl` / `lsp` / `wdoc {build,serve,pdf,markdown,skill,comments}` (review comments live in `wcl editor`'s preview pane and persist to `comments.wcl` sidecars — no document rebuild; `comments` lists/`resolve`s them. `serve` is the plain watch/rebuild/live-reload dev server — editing lives in `wcl editor`) / `answer` (guided answer mode over `@answerable` question blocks from `import <answer.wcl>` — `--list` JSON, `--id`/`--pick`/`--text`/`--skip` for scripts, or an interactive walk-through with arrow-key menus via `stty` raw mode falling back to numbered line input; see `src/answer.rs`) / `wskill {check,install,graph,lint,audit,op}` (`src/wskill.rs` — the CLI face of `wcl_wskill`; `op` reads the library's op JSON from `--op` / `--file` / stdin, applies each one against a freshly loaded model and commits it through `edit::commit`, so a refused or schema-violating op rolls back and stops the run, and `--dry-run` prints the op list instead. Ops resolve against the **wskill root**, whatever entry the caller named) / `editor` (browser editor for the current directory, `src/editor/`: gitignore-aware file tree (`ignore` crate walk), tabbed CodeMirror editing of any text file (the embedded `editor-ui/` SPA), `.wcl` LSP — completion/hover/diagnostics — over a WebSocket↔duplex bridge to an in-process `wcl_lsp` session (`src/editor/lsp_bridge.rs`; the server rewrites `initialize` to inject `initializationOptions.root`), and a site-scoped wdoc preview pane: `GET /api/sites` discovers every `site`-declaring entry under the served tree (nested by `include` membership) for a topbar picker, and a manual Rebuild builds the selected site with unsaved buffers overlaid — on a warm output dir it re-renders only the page the iframe shows; pages that leaves stale are lazily materialized server-side when navigated to (per-slug `PreviewSession`s remember the last build's inputs; the html→page mapping comes from the `_wdoc/pages.json` manifest full builds write), with automatic full-build fallback whenever targeting isn't possible — cold dir, unknown page, page-set drift, decks, new icons. Two questions have exactly one owner each in `src/editor/preview.rs`: **where a build lands** is `PreviewTarget::slug` (a readable prefix plus an FNV-1a suffix over the exact fields — the prefix alone collapses every non-alphanumeric byte, so `docs/main.wcl` and `docs_main.wcl` would name one directory and serve each other's pages), and **what it renders** is the `BuildPlan` that `BuildRequest::plan` (a POST, against the recorded session: no session ⇒ cold dir ⇒ full) and `PreviewSession::lazy_plan` (a navigation) both answer and `run_preview_build` merely executes from a `BuildJob`. Client-side the whole protocol — request, in-flight suppression, cache, staleness — belongs to `editor-ui/src/state/preview.js`: a host declares a target and mounts what `createPreview` returns; page addressing and the manifest probe are its pure helpers in `editor-ui/src/preview/pages.js`, and staleness is a **subscription** to the commit bus (`editor-ui/src/state/commits.js`, whose event names only the surface a commit left current) keyed by the surface identifier a commit carries, not a flag each component must remember to set. The five iframe hosts (preview pane, design canvas, both content-modal preview tabs, screen editor) are hosts of one; the pane and the canvas share the app-lifetime `mainPreview` because they are two views of one surface (`comment_mode` + `edit_mode` anchors on, no injected scripts; root = explicit arg, else `./main.wcl` — needed only for schema-validated saves, the LSP root, and the review handshake). The preview pane also hosts the **review-comment UI** (comment on page / pick a block / list-edit-resolve, pins re-placed per iframe navigation — `src/editor/comments.rs` + `editor-ui/src/{preview/frame.js,state/comments.js,components/CommentPanel.jsx}`, endpoints `/api/comments*` + `/api/review/*`) and the **edit_object jump** (an "Edit this …" button in the rendered page resolves its object via `POST /api/object/locate` and opens the declaring `.wcl` in a tab selected at the instance — see the wdoc feature map). Saves run the validating `commit` pipeline with etag conflict detection; non-root `.wcl` buffers get syntax-only LSP diagnostics (isolated schema validation would be all false positives)). → see the `wcl` wskill (`docs/wskills/wcl/`) and `wcl --help`.
- **`wcl_wskill`** — the wskill model as typed Rust: `Graph` (topic, registry-declared `View`s, `Unit`s with audience + visibility + body-block lists, nested `Index` trees, `related`/pin `Edge`s, an `n`-ordered `Course`), every node anchored to its declaring file + span, `related_editable` marking a computed list that must not be rewritten, and `unindexed()` / `indexes_pinning()` / `shows_in(view)` queries. Loadable from the working tree, an open `Document`, or a git revision. `ops` carries the id-addressed op vocabulary the curator and the editor share, plus its JSON dialect (`from_json` / `to_json`), so both hosts read one wire form. Plus `lint` (`src/lint.rs`): eleven rules over that model at three severities — three mechanically-certain errors, three warnings with a real exception rate, five thresholded curator nominations — every threshold a documented constant, every finding `{severity, rule, unit, file, span, message}`, and no writes. Plus `audit` (`src/audit.rs`): a git `Range` (`a` / `a..b` / `a...b`, defaulting to `HEAD~1` against the working tree) loaded at both ends and diffed into the **union graph** — every node of either revision carrying a `Change` and, for a modification, which `Aspect`s moved; every edge likewise; findings riding the nodes, scoped two ways (everything wrong with a node the range **touched**, only what it newly **broke** in one it didn't); and eight health metrics paired across the two ends, each oriented so lower is better. A revision where the wskill doesn't exist yet is `Graph::absent`, not an error — the commit that created a wskill audits as everything added. → `wcl wskill check` / `install` / `graph` / `lint` / `audit` / `op` and `cargo doc`.
- **`wcl_lsp`** — diagnostics, formatting, document symbols, workspace symbol search, go-to-def + find-references (cross-file), hover, completion, signature help, semantic tokens (incl. `${…}` slots), schema-violation code actions, incremental sync (`ropey`), TCP listener. Resolves cross-file lookups through a root document; open buffers shadow disk via an overlay `FileLoader`. → see `cargo doc` on `wcl_lsp`.

**Implementation contracts** (non-obvious rules a contributor must respect, not in docs/):

- `let` **items** (`let name = expr` at file/block scope) are composition helpers: resolvable by name in sibling/descendant expressions but **invisible** to `Document::fields`/`blocks`, `get`, JSON, and schema validation (not in the symbol index). Distinct from the expression-level `let … ;` inside `{ }` blocks.
- **Bare record literals** (`{ name: value, … }`) coerce to the matching `Value::Variant` **by shape** when the declared type is a union or `list<union>` (`variant_dispatch::coerce_value_to_type`, run from `Field::value`, `build_variant`, and `invoke_fn_value`). The explicit `Union::Variant { … }` form overrides; no match ⇒ `VariantNoMatch`.
- **`@document` schemas compose per namespace.** The effective document schema for a namespace is the *merge* of every `@document` type visible there (`Document::doc_schemas_for_ns` → `DocSchemas` in `crates/wcl_lang/src/doc.rs`): a top-level field/block is legal if any member declares it, root-authored declarations preferred for type checks. Origin comes from `TypeDecl::is_imported` (set from the source's import path). `MultipleDocumentSchemas` fires only on a **second root-authored** `@document` in a namespace — imported (library) ones merge silently. This is why a user can `import <wdoc.wcl>` and still declare their own root `@document` to add top-level tags. Both the strict path (`schema_errors`) and the lazy path (`Field::schema_membership_error`/`declared_type_ref` in `doc/views.rs`) must consult the merge. **Corollary: gather-field names share the merged space** — a user `@document` field named like a wdoc one (`components`, `pages`, `sites`, `bodies`, …) resolves ambiguously and silently breaks template iteration (`each = components` fails as "unresolved reference" only at build time); the WAD schema gathers component instances as `sw_components` for exactly this reason.
- **`@declares_kind` makes an *instance* declare a block kind, and the language derives that kind's schema.** A `@block` type carrying `@declares_kind(name = 0, params = "slots", body = "body")` (wdoc's `WdocComponent`, in `crates/wcl_wdoc/lib/components.wcl`) says its instances declare kinds; `Document::block_schema` falls back to a schema derived from the declarer's param blocks — one `@schemaless utf8` field per param, optional when the param carries a `default`, the rest listed in the derived `@block(kind, required_fields = [...])`, plus `@contextual` because an instance emits whatever the declarer's body expands to. So a component instance is an **ordinary block**: the generic `UnknownField` and `required_fields` checks catch a misspelt or unfilled slot, and there is no second slot-checker in the language. Three consequences a contributor must respect: (1) the derived storage is a lazily-built `OnceLock` arena on `Document` (`declared_kinds`, which also serves `kind_declarer` — the old `component_index`), guarded against the re-entrancy of deriving-while-evaluating by the `deriving` thread set; (2) a derived schema is deliberately **absent from `type_decls()`** — it isn't a declaration, so anything introspecting by walking declarations won't find it and must go through `block_schema` / `derived_block_schema` / `TypeDecl::is_derived`; (3) the collision check and the derivation itself look kinds up **without** the fallback (`find_schema`), or a declared kind collides with itself. Param *values* are not type-checked — a param is filled with whatever the host's expander binds to it.
- **The wskill library is embedded, not copied** (`crates/wcl_wskill/lib/`, registered by `src/stdlib.rs`): the base schema, the two optional view schemas, the eight per-unit page components, the five book pages and the book projection. The two view schemas ship **unconditionally** — declaring the `lesson` / `presentation` block types costs a wskill nothing until it authors one, where before each topic imported them by hand. A wskill's root document opts in with `import <wskill.wcl>` (the everything prelude — schema parts only, since a projection declares a `site` and a document is one projection at a time) and each projection entry imports the projection it is (`import <wskill/book.wcl>`). **Overriding is import granularity — there is no shadowing.** A topic that wants its own part doesn't import that part and declares its own, enumerating the rest (`docs/wskills/wcl/wdoc/book/main.wcl` and `docs/wskills/wdoc/wdoc/book/main.wcl` are the two in-repo cases); an *additive* extension needs no override at all, just a file of its own beside the shared parts (`docs/wskills/wcl/wdoc/component/signature.wcl`). Topic-owned vocabularies (entity kinds, artifact kinds) stay in each wskill's hand-editable `schema/kinds.wcl`, declared in the same `wcl.wskill` namespace so the embedded schema's bare `EntityKind` resolves to them. `wcl_wdoc` must not know any of this (spec `05-wskill.md` §5.2), and it builds every loader itself, so the library reaches it through a slot: `wcl_wdoc::install_stdlib` layers a registry onto `schema_registry()`, and `wcl_wskill::install_stdlib()` (idempotent) is called from `wcl`'s `main`, from `Graph::open` (the only loader that opens a document — `from_document` is handed one) and from the editor's test fixtures, which never run `main`. **Registry imports are importer-relative**, so a part under `wskill/component/` reaches wdoc as `<../../wdoc.wcl>`; `stdlib.rs`'s own test walks every part and fails on a path that names no registered key. Scaffold `file`/`folder` blocks accept a `when: bool?` gate (conditional generation — the wskill template's optional presentation/training views use it), and `include` blocks / `included_sites` accept a `prefix` output override so two includes over one folder (a member's book + its deck) target distinct subdirs.
- **A wdoc block declares exactly one rendering, and `@native` is the other half of `lower`** (`crates/wcl_wdoc/src/native.rs`). A type extending a lowering interface (`WdocBlock` / `SvgBlock`, transitively) carries **either** a `lower` field **or** `@native`; both, or neither, fails the build (`native_errors`, reached with `reserved_kind_errors` through the one `build::contract_errors` gate all four entry points call). `lower` is therefore declared *optional* on the interfaces — the check, not the type system, is what makes it exactly one, which is what killed the 57 stub `lower`s that returned `[]` while Rust intercepted the kind. `@native(backends = [:html, :markdown, :skill])` names the targets that implement the kind (bare `@native` = all four) and is cross-checked **both ways** against `NATIVE_DISPATCH`, the one Rust table of natively-dispatched kinds: a target claimed but not implemented, or implemented but not claimed, is an error rather than the next stub. **Not in the registry, and now empty**: a block with a real `lower` that a backend nonetheless special-cased — a hand-copy of a lowering the backend couldn't follow, not a native implementation. There were two, `callout` and `code` (Markdown), and the semantic content IR took both; there is nothing of that shape left to exempt. Rendering a native block on an uncovered target is a build error (`refuse_uncovered`), waived per instance with `@except(backends = […])`: capability says *can't*, intent says *don't want to*. **Two targets must cover it**, because two are involved: the backend actually rendering (each dispatch passes its own — `render_block` always passes `Html`, since a `card` body is HTML in whichever target embeds the SVG) and the output the build is producing (`patterns.backend()`). `markdown_source` is a renderer question, `file` an output one, and a `file` inside a card must not reach a PDF just because the card body renders as HTML; in the ordinary case the two are the same backend and it is one check. Adding a Rust arm for a kind means adding its registry row **and** its `@native` declaration; adding a backend to a kind means widening both.
- **The editor has ONE kind model** (`crates/wcl/src/editor/kinds.rs`). Every surface that describes a data-object kind — the palette, the Systems view and its details modal, the graph, the nav model, Data mode, the create path — reads `KindModel` and serves the same wire shape (`kind`, `type_name`, `doc`, `fields`, `has_body`, `accepts_children`, `child_families`, `parents`, `refs`, `edge`, `id_field`, `suggestions`), so the client has one reader. `type_name` is **always the fully-qualified schema name** (`wcl.wad.Container`), because that is what the create path matches on; a bare kind name silently falls back to a first-declared-wins lookup, which is the namespace collision the field exists to prevent. `suggestions` is the only member derived from instance data (it forces evaluation of every block of the kind) and is therefore opt-in — the Systems view asks, the palette must not. The split of responsibility is by where a fact is TRUE: generic document facts (`Document::{gathered_kinds,gather_field}`, `TypeDecl::{child_families,declares_body}`, `TypeField::element_decl`) live in `crates/wcl_lang/src/doc/gathers.rs` so `wcl wdoc` and the LSP can read them; editor *conventions* (a scalar `identifier` field named after another gathered kind is a parent link, a kind carrying `source` + `destination` is an edge, repeated free-text values are suggestions, the palette denylist, wdoc's own infrastructure gathers being excluded) stay in `kinds.rs` and must not leak into the language. **The model is the interface**: `kinds.rs` hands out no `Document`, and a nested kind is reached by naming its family (`describe_family`) rather than by passing a `TypeDecl` back in, so a surface cannot grow a twelfth walk over the type declarations beside the one everything else reads — a consumer that needs a new schema fact adds it to `Kind`. Where a new block goes is a separate body of knowledge again (`editor/placement.rs`), what the add-block UI can insert is a third (`editor/palette.rs`, `GET /api/palette`: the model's unit and diagram kinds plus a curated body-block list and the tree's `wdoc_component`s), and the readers several endpoints share — labels, scalar-to-string, repo-relative paths, span parsing — are a fourth (`editor/util.rs`; block-source classification stays in `blocks.rs`, which owns the shape it defines). Test the model against a schema written as a source string via `Document::open` — no temp dir, no editor state, no preview tree.
- **`wcl init` evaluates the template twice** (`src/scaffold/mod.rs`). Pass 1 opens the document with an `answer` builtin that returns `none` and reads only the `property` blocks (lazy eval never forces the `file`/`folder` bodies). After answers are resolved, pass 2 re-opens with `answer("name")` bound (a captured-closure builtin over the answers map, via `from_fn` + `Environment::add_builtin`) so heredoc `${answer(...)}` slots substitute; the file content **must** use the interpolating heredoc form `$<<TAG` (plain `<<TAG` is literal). Instance fields use `=` (`prompt = "…"`), not the `:` of `type` declarations. Answer `.wcl` files are read by evaluating their top-level field expressions off the AST (`parse_for_edit` + `eval_expr`), bypassing the strict `@document` membership check a bare `key = value` file would otherwise trip.
- **A `wcl editor` handler takes the narrowest context it can, and its tests live in its own module.** `editor/workspace.rs`'s `Workspace` (the served tree + the optional root document, plus the sandboxing / doc-entry / overlay helpers every request needs) is what a read endpoint gets; a **write** path additionally gets `preview::Sessions`, whose only public method is `invalidate()` — call it after every successful `commit`, or a built preview keeps serving pre-commit HTML on the lazy per-page GET. Only `editor/preview.rs` takes the whole `EditorState` (it alone needs the scratch tree, the session map and the build gate); `lsp_bridge` clones a `Workspace` for the connection rather than holding the state. Consequently `editor/mod.rs` holds the routing table (first in the file) and, below it, **the transport tests plus the handful of helpers it still owns** (`locate_object`, `resolve_root_file`) — routes resolve, `conflict:` → 409 / missing record → 404, sandbox refusal, the SPA fallback, the LSP upgrade, and the end-to-end guard that a write invalidates built previews. Everything else is tested by the module that owns it, by calling the inner function directly. Shared fixtures live in `editor/testsupport.rs`: `workspace_with(doc)` / `workspace_built_by(|root| …)` are the one-line setup, and a test that *writes* blocks drives `Edits`, which re-resolves each op's target block at request time — every commit reformats, so a span read before one request is stale by the next, and no test should be carrying one across. Adding an endpoint means adding its test *there*, not to the module of record. The editing core itself (`crates/wcl/src/edit.rs` — `commit`'s write/validate/rollback, `content_etag`, `format_source`, `locate_object`) carries its own tests too.

## `wcl_wdoc` feature map

**Mechanism:** an unrecognised block kind in a diagram/page dispatches to a WCL
`<kind>_lower` fn returning `list<Content | SvgFundamental | HtmlFundamental | TermFundamental>`,
which the renderer recurses (depth-limited) until only leaves remain — a fundamental, or a
node of the semantic content IR, which terminates the recursion on every backend rather
than only in HTML. This is how user-declarable `@block(...) extends SvgBlock` (etc.) shapes
plug in. A page-level block
that draws SVG (`sequence_diagram` / `state_diagram`) must still satisfy `WdocBlock`
(whose `lower` returns HTML fundamentals), so its geometry lives in a second `lower_svg`
fn; `render_lowered_svg_block` (`src/render/svg/standalone.rs`) fits a viewBox over the
result and all three backends dispatch to it. A block that can't lower says so with
**`@native`** instead (terminal, card, node_table, tree, timeline, tilemap, dopesheet, map,
wireframe widgets, icons, table, list, and every structural wrapper), because its output
(calendar math, ANSI grids, external-image crops, measured widget layout, valid nested list
HTML) isn't expressible in WCL — see the `@native` contract below; there are no stub `lower`s
any more. `code` and `math` are **not** native: they have real `lower`s emitting the
`Highlighted` / `Math` leaf fundamentals, i.e. Rust computes one bit of a WCL-built
structure. The wireframe `wf_*` family `extends SvgBlock`, so a widget is a diagram shape
(placed by `x`/`y`, connectable by edges), not a page block. Everything deeper → the doc page
or the source.

## Intentionally deferred

Deliberate, comment-documented gaps (not bugs), tracked so the list stays honest:

- **Richer value-type introspection in interface checking** — `crates/wcl_lang/src/doc/eval.rs` `check_value_implements_iface` structurally introspects variant-with-record and bare-record values; closures, lists, tensors, and scalars get a pass-through until the language carries runtime type tags for them.
- **Type arguments on `TypeRef::Named` are syntax only** — `content<SvgBlock>` parses (`crates/wcl_lang/src/parser/types.rs` `parse_type_args`), prints, and is readable via `TypeRef::type_args()`, but nothing checks arity, nothing substitutes, and there is no `type Foo<T>` declaration form. A named type resolves by `path` alone, so `content<Nonsense>` parses and only fails later (if at all). This is enough for slot derivation, which emits both a typed field and a `@children(X)` decorator and lets the decorator do the child-kind checking. Full generics are a separate effort.
- **Only the prose blocks lower to the semantic content IR so far** — `callout`, `chapter_header`, `code`, `footnotes`, `p`, `text` and `h1`..`h6`. The rest still lower to `HtmlFundamental`, and each backend keeps its `HtmlFundamental` walker (still catch-all-ended) beside its exhaustive `Content` one. Deliberate: `callout` was the tracer bullet, and the concepts move over one at a time (#43 classifies the remainder). The IR arms nothing lowers to yet are not speculative — a user block may lower to any of them today, and the tests exercise that.
- **A `text` block's `span` children lose their `id` / `class`** — the IR has no inline-run concept, so a `text` concatenates its spans into one `Content::Paragraph`. Outside HTML this changed nothing (the Markdown and PDF walkers already flattened a `text` to its child text), but in the book a `span "…" { class = ["accent"] }` stopped painting. The fields stay declared so existing documents keep validating; carrying them back needs an inline-run node in the IR, which is its own decision.
- **A derived kind schema's param fields are permissive** — `crates/wcl_lang/src/doc.rs` `derive_kind_schema` types every param `utf8` and marks it `@schemaless`, so only presence is checked, never the value. Deliberate: wdoc's `wdoc_slot` declares no type for a slot to carry, and a param is filled with whatever the host binds to it. When params grow declared types (spec `spec/wdoc-substrate/01-language.md` §1.3, the `content<SvgBlock>` shape), the derivation emits the declared type plus a `@children(X)` decorator and the permissiveness goes away.
- **`if let` still requires its `else`** — a plain `if` may omit the branch (the untaken side is `none`, `crates/wcl_lang/src/parser/expr.rs` `parse_if_expr`), but `if let` does not; `eval_if_let` would happily return `none` on a no-match, so this is scope, not a semantic obstacle.

New deferred items get tracked alongside the slice that introduces them.

## Verification

A task is **not done** until the merge bar passes:

```bash
just ci::check
```

That's the **`ci` just module** (`.just/ci/mod.just`) — the whole gate. `just ci::<part>`
runs one part, which is exactly what each step of `.github/workflows/ci.yml` invokes, so
the workflow and the local gate can't drift. While iterating, the three parts that fail
most are worth running alone:

```bash
just workspace-test    # unit + integration tests across the workspace
just workspace-lint    # clippy --workspace -- -D warnings
just fmt-check         # cargo fmt --all -- --check
```

A module can't see its parent's recipes, so the gate's constituents live in
`.just/shared.just`, imported by **both** the root justfile and the module (each defined
once; `just workspace-test` and `just ci::workspace-test` are the same recipe). Two
deliberate exceptions: `just ci::fuzz-sweep` is a part but not in `check` (it needs nightly
+ cargo-fuzz, and runs as its own CI job), and `wad-extract-check` is the one part that
isn't side-effect-free — it regenerates the tracked files under `.wad/data/generated/`,
which is how it judges their freshness.

Run benches with `just workspace-bench` when changing the parser hot path.

## Conventions

- Hand-written lexer + recursive-descent parser. No nom, no parser generators.
- Diagnostics use `miette` + `thiserror`. Every parse error carries a `Span` and a `NamedSource` so the CLI can render snippets.
- Keep the dependency list minimal. Add a new crate only when it earns its place.
- **Don't mention `file://` in docs or code comments.** When explaining that an
  asset resolves only over a server (not a direct local-file open), say "when
  served / hosted" and "not opened directly from disk" — never write the
  `file://` scheme.
