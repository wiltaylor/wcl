# WCL — Claude Code Instructions

This branch (`rewrite`) is a clean restart of WCL. The previous implementation lives on `main` — do not consult it for current behaviour.

## Layout

- `crates/wcl_lang` — language library: lexer, parser, AST, document view, lazy evaluator, schema validator, host-binding API
- `crates/wcl` — `wcl` CLI binary (`wcl parse`, `wcl check`, `wcl eval` / `wcl get`, `wcl set`, `wcl fmt`, `wcl repl`, `wcl lsp`, `wcl wdoc build`, `wcl wdoc serve`)
- `crates/wcl_lsp` — `tower-lsp` language server driving `wcl lsp`
- `crates/wcl_wdoc` — library crate driving the `wcl wdoc` subcommands: `wcl_wdoc::build(file, out_dir)` renders pages to HTML, `wcl_wdoc::serve(file, out, addr)` runs the watch+axum dev server. Ships its standard library as `include_str!`-embedded `lib/*.wcl` modules registered (under `wdoc/*.wcl` keys) into a `wcl_lang::Registry` by `build.rs`'s `schema_registry()`; `build` prepends a single `import <wdoc/prelude.wcl>` line to the user source (so user diagnostics shift by one line, not ~1.5k) and parses via `Document::open_at_with_loader` with `registry.loader(disk_loader())` — the registry serves the angle-bracket system imports, real disk imports fall through. `lib/prelude.wcl` pulls in every part (`core` / `diagram-core` / `charts` / `templates` / `terminal` / … — split purely for navigability; name resolution is order-independent across imports, and a single byte-for-byte partition of the old monolith). The schema defines fundamental blocks (`page`, `text` + `span`, `column`, `diagram` + shapes `rect` / `circle` / `line` / `label` / `polygon` / `container`), the layout + anchor system on container and shapes, and `class` for styling (a `class` may carry `dark {}` / `light {}` mode blocks — dark is the default, light applies under `@media (prefers-color-scheme: light)`, and a `:root[data-theme=…]` set by the `book` template's optional `theme_toggle` button overrides either; built-in book CSS uses bare-class selectors so user classes override it, and `<body class="wdoc-body">` is the page-background hook). **User-declarable custom shapes**: any `@block("kind") type ...` paired with a top-level `kind_lower = fn(...) -> list<SvgFundamental>` (or `list<HtmlFundamental>`) plugs into the renderer — when an unrecognised block kind appears in a diagram or page, the renderer calls its `<kind>_lower` function and recursively lowers the returned variants until only fundamentals remain (depth-limited, error-marker on overflow). The stdlib uses exactly this mechanism: `h1`..`h6` lower to `Paragraph` variants, and `process` / `decision` / `terminator` lower to SVG primitives. **Data charts**: `bar_chart` / `line_chart` / `pie_chart` are stdlib SvgBlocks that lower to fundamentals via pure-WCL geometry (using the math builtins). Data is a `series: list<ChartSeries>` of `ChartSeries::Of { name, values }` (bar/line — multiple series, grouped bars / multi-line) or `slices: list<ChartSlice>` of `ChartSlice::Of { label, value }` (pie, drawn as polygon-approximated arcs); set the scale with `y_min`/`y_max` (auto-fit when omitted) and label via `title`/`x_label`/`y_label`/`categories`. Every bar/line/slice is auto-tagged with a cycling palette class (`wdoc-series-1`..`wdoc-series-8`) and emits no inline fill, so colour comes from CSS; axes/grid/labels/title/legend paint with `currentColor`. Default chart styling is the `CHART_CSS` constant (injected before user classes); recolour a series by redeclaring its palette class — e.g. `class "wdoc-series-1" { fill = … dark {…} light {…} }` (quoted because the name has hyphens). This works because `class` now also emits SVG paint properties (`fill`/`stroke`/`stroke_width`/`opacity`), so the class system themes diagram shapes the same way it themes text. **Timelines**: `@block("timeline")` (`lib/timeline.wcl`) is another pure-WCL SvgBlock in the charts family — a labelled axis, `direction = :horizontal` (default) / `:vertical`, that lowers to fundamentals via orientation-neutral geometry helpers (`tl_x`/`tl_y` map a `(frac, perp)` pair to a point for either orientation; it reuses `chart_fmt`/`chart_series_class` from `charts.wcl`). `items: list<TimelineItem>` (two variants — `Of { label at }` auto-alternates the side, `Sided { label at side }` forces `:near`/`:far`) draw a marker + lead line + label; `phases: list<TimelinePhase>` (`Of { label from to }`) draw perpendicular boundary divider lines with a heading, each cycling `wdoc-series-N`; the scale is numeric `t_min`/`t_max` (auto-fit from the data when omitted) with an optional `step` for tick labels (generated by filtering a fixed integer range, since WCL `range` is i64-only and the scale is f64). Styling is the bundled `wdoc-timeline-*` classes (axis/marker/connector/label/divider/phase-label) in `css-classes.wcl`, so a site `theme` or a `class` override recolours it like a chart. A timeline also accepts rich-text **cards** as event items (see below). **Cards**: `@block("card") extends SvgBlock` (`lib/card.wcl`) is a diagram box whose body is arbitrary wdoc content (`@children(WdocBlock) body` — inline-formatted text, lists, code, callouts, nested diagrams). Because it's an SvgBlock it's a legal child of any `diagram`/`container` (positioned by `x`/`y`/anchors like a `rect`, connectable via `connect_points`). Like `map`/`tilemap` it's special-cased in Rust (`src/card.rs`, its WCL `lower` a stub): the body is HTML produced by `render_block` + the inline engine, which WCL can't express, so the renderer wraps it in an SVG `<foreignObject>` holding a `<div xmlns="http://www.w3.org/1999/xhtml" class="wdoc-card">` (always-visible, scales with the diagram — the codebase's only `<foreignObject>` use; relies on `text/html` parsing). `render_card` (free shape, box via `resolve_rect_box`) and the timeline (event cards) share `render_card_foreign`. **Timeline cards**: a `timeline` declares `@children("card") cards`; the WCL `lower` reads each card child's `at`/`side`/`width`/`height` (geometry stays single-sourced — `block_to_record` materialises `@children` lists as records) to auto-fit the scale and emit a marker + connector + a `SvgFundamental::Card { x y width height index }` carrier; `src/timeline.rs` (the `timeline` render_shape arm, mirroring `map`) intercepts each `Card` variant, resolves its `index` to the Nth `card` child, and draws the `<foreignObject>` at the computed box. Default styling is the `wdoc-card` `stylesheet` (structural, neutral); a themed site recolours `.wdoc-card` via the theme apply rule in `render/theme.rs` (beside `.wdoc-map-card`). A timeline with no card children renders byte-identically to before. **Syntax-highlighted code blocks**: `@block("code") { @inline(0) language source }` renders via `syntect` (pure-Rust `fancy-regex` backend) plus `two-face`'s curated extra grammars (Rust, Python, TS, TOML, Dockerfile, …) — emits `<pre class="code-block"><code class="language-X">` with `<span class="tok-…">` tokens; an unknown language tag falls back to plain text. A bundled `wcl.sublime-syntax` grammar makes the site self-highlighting; the bundled `code-theme.css` ships token colours that get injected into every page's `<style>` and can be overridden by user `class` blocks. **Math equations**: `@block("math")` typesets a LaTeX equation to a self-contained inline SVG via the pure-Rust **RaTeX** crates (`ratex-parser` → `ratex-layout` → `ratex-svg` with the `embed-fonts` feature + `embed_glyphs`, so glyph outlines embed as `<path>`s from the binary-embedded KaTeX fonts — it works on a `file://` open, no webfonts). Like `code` it emits a Rust leaf fundamental: the `math` lower returns `HtmlFundamental::Math { latex display class }`, rendered in `math.rs` (`render_math_fundamental` → the shared `math_svg`); the source goes in the block's `@inline(0)` slot, so `math "E=mc^2" {}` or a raw heredoc `math <<'TEX' … TEX {}` both work. Inline prose math comes from two built-in `inline_pattern`s — `$…$` (text style) and `$$…$$` (display) — emitting `InlineSpan::Math` rendered by the same helper (`render_inline_math`, the `"Math"` arm in `inline.rs`); the `$…$` regex requires a non-space char at each delimiter so currency (`$10 or $20`) is left alone. The SVG is re-wrapped and sized in `em` from the display list's own metrics (inline baseline-aligned via `vertical-align:-{depth}em`), and `force_current_color` rewrites RaTeX's default-black `fill="rgba(0,0,0,…)"` to `currentColor` so equations follow the surrounding text colour (theme / `class` / light-dark toggle) while an explicit `\textcolor` survives. The pipeline runs under `catch_unwind`; bad LaTeX ⇒ an inline `.wdoc-math-error` marker, never a build failure. The `wdoc-math` stylesheet (in `lib/math.wcl`, auto-injected) centres block equations and uses no `--wdoc-*` vars, so a `site`-less doc stays unthemed. **Terminals**: `@block("terminal")` renders a monospace character grid as inline SVG, drawn with a bundled JetBrains Mono Nerd Font Mono (Regular/Bold/Italic woff2, `include_bytes!`d, written to `<out>/_wdoc/` only when a doc uses a terminal and referenced by `@font-face` in the `TERMINAL_CSS` constant). Like `code` it's special-cased in Rust (`terminal.rs`) — its `lower` is a stub; the grid model + ANSI handling + asciinema replay aren't expressible in WCL. One styled `Grid` (`Cell{ch,fg,bg,style}`, `Color::{Default,Indexed(u8 0-255),Rgb}`) is populated three ways: **authored primitives** (`term_box` with `:single`/`:double`/`:rounded`/`:heavy`/`:ascii` borders, `term_text`, `term_glyph`, `term_fill` — children of the `TermPrimitive` interface placed at 1-based `row`/`col`, carrying the full style set: fg/bg as `#hex`/index/ANSI-name + bold/dim/italic/underline/strike/blink/inverse/conceal); **inline `text`** fed to the `avt` virtual terminal (bare `\n`→`\r\n`); or **replay** of a `source = "rec.cast"` asciinema recording (parsed with `serde_json`, replayed through `avt` into coalesced frames). One renderer (`grid_to_runs` + `runs_to_svg`) paints a background `<rect>` per coloured run, then **one centred `<text>` glyph per occupied cell** on an integer-pixel grid (a true character grid — block/box-drawing glyphs tile seamlessly, no vector-shape special-casing). **Theming is via the `class` system**: the terminal's `class` list reaches the wrapping `<div>`, so a `class "x" { background = … color = … dark{…} light{…} }` sets the window background (the `<div>` background) and default text colour. Default-coloured cells emit `fill="currentColor"` (themed by the class `color`, dark/light included) and no bg rect (the `<div>` background shows through); only explicit ANSI/`#hex`/indexed colours carry inline fills. `fg`/`bg` fields and `palette = :light` are explicit overrides (inline `style` on the `<div>`); `.wdoc-terminal` in `TERMINAL_CSS` is the bare-class default theme (dark) that user classes override. The same defaults seed the palette's concrete values so inverse/dim cells match the theme. The bundled `terminal-player.js` (written to `_wdoc/`, loaded once per page) rebuilds the SVG cell group from the per-frame run JSON embedded next to it. Replay controls: a big centred overlay play button (`.term-overlay-play`, an HTML `<button>` over the terminal) plus a monochrome play/pause/replay glyph the renderer draws in the chrome left of the `✕` (`.term-chrome-btn`, an SVG `<text>` the player swaps between play `▶`, pause `❚❚`, and replay `↻` — text-presentation glyphs that follow `currentColor`; `⏸` U+23F8 is avoided because Chrome forces it to a colour emoji); there's no scrubber or speed dropdown (playback rate comes from the `speed` field). Playback **stops at the end** (overlay + chrome glyph flip to `↻`; click to replay from the top) unless `loop` is set, in which case it restarts seamlessly. `cols`/`rows` size the grid (a `.cast` header overrides them); `chrome` draws a title bar with a close `✕` on the right; bad `source` ⇒ inline error marker, not a build failure. **Tables**: `@block("table")` authored with WCL's native pipe-row syntax (`rows: | a | b |`, first row = header); cells render through the inline-pattern engine; lowers to an `HtmlFundamental::Table`. **Icons**: full **Lucide** (ISC) + **Bootstrap Icons** (MIT) packs are vendored under `crates/wcl_wdoc/assets/icons/<pack>/` (with their `LICENSE`s) and compiled into the binary by a `build.rs` codegen step (one concatenated blob + a name-sorted `(name,offset,len)` index per pack → `$OUT_DIR/icon_manifest.rs`, `include!`d by `icons.rs`); there is **no** runtime directory/disk read. An `@block("iconset")` names a reference to a `pack` and sets default styling (`size`/`color`/`fill`/`background`/`class`), with per-icon `@block("icon_def")` children overriding by name; `@children("iconset")` hangs off the document root. Icons are used three ways, all special-cased in Rust (like `code`/`terminal`, because the SVG comes from the compiled-in registry, not WCL): the built-in `inline_pattern icon` (`:name:` / `:set.name:`) produces an `InlineSpan::Icon` that `inline.rs`'s `render_variant` resolves to `<svg class="wdoc-icon"><use href="_wdoc/icons.svg#pack-name"/></svg>` (a registry miss — unknown name or no iconset — emits the literal `:name:`, so prose like `10:30` is safe); a placeable `@block("icon") extends SvgBlock` (`name`/`set`/`x`/`y`/`width`/`height`/`scale`/anchors) is special-cased in `render_shape` to a positioned `<use>` (sharing the `SvgBlock` interface so it's a legal `diagram`/`container` child, and getting an explicit arm in `collect_shape_positions` so its bbox isn't driven by its name label). Rather than inline every occurrence, the build records each used `(pack,name)` in an `IconRegistry` (`RefCell<BTreeSet>`, stored inside `InlinePatterns` for inline rendering and reached on the SVG path via `patterns.icons()` → `render_diagram`/`render_layout_children`/`render_shape`/`render_container`/`render_grid_children`/`render_layered_children`), then writes one shared `_wdoc/icons.svg` sprite (a `<symbol>` per used icon, via `normalize_to_symbol` regex surgery that preserves the root presentation attrs — `fill`/`stroke`/`stroke-width` — and the `viewBox` but drops `width`/`height`/`xmlns`/`class`). Because the sprite is referenced by `<use href>`, the output is small but icons only resolve when **served / hosted**, not via a direct `file://` open (same limitation as the terminal assets). **Theming rides the `class` system**: every icon paints with `currentColor`, so a `color` (on the iconset, an `icon_def`, an `icon` block, or a referenced `class`) is the universal foreground knob (it recolours both stroke-based Lucide and fill-based Bootstrap); `size` scales inline icons (default `1em`, via the `svg.wdoc-icon` selector in the always-injected `ICON_CSS` so it never touches the size-by-attribute diagram `<use>`s), and `fill`/`background` are optional overrides emitted as inline style (so an explicit `color` wins over a class `color`). **Icon as a shape property**: box-like shapes (`rect`/`circle`/`container`/`process`/`decision`/`terminator`, plus any custom `extends SvgBlock` shape that declares the same fields) accept `icon`/`icon_size`/`icon_pos`/`icon_class` (`IconPos` = `:center`/`:top_left`(default)/`:top_right`/`:bottom_left`/`:bottom_right`/`:left`/`:right`). The renderer post-injects the badge in `render_shape` via `with_shape_icon` → `shape_icon_box` (the shape's bbox, mirroring `collect_shape_positions`) → `place_icon` → the same `resolve_shape`, drawn over the shape (after it) so it reuses the sprite + iconset styling + class theming; it needs no `SvgFundamental::Icon` and no WCL-lower change (the `icon` block itself is exempted — it *is* an icon). **Callouts**: `@block("callout")` is an admonition (icon + coloured heading + body) that — unlike `column`/`code`/`terminal` — is **not** special-cased in Rust; it ships a real WCL `lower` that composes plain `Element`/`Paragraph` fundamentals plus a new `HtmlFundamental::Icon { name class? }`. The built-in types `note`/`info`/`tip`/`warning`/`error`/`success` are selected by putting the name in the callout's `class`; the `lower` picks each type's default icon (a `lucide.<glyph>` — `info`/`lightbulb`/`triangle-alert`/`circle-x`/`circle-check`) by `list_contains` on the class list, and `CALLOUT_CSS` keys the accent on `.callout.<type>` via a `--callout-accent` custom property (so only the heading/border/icon are coloured, not the body). An explicit `icon` field overrides the default. The `Icon` fundamental is the one piece needing Rust: `render_html_variant`'s `"icon"` arm calls `IconRegistry::resolve_html_icon` (so usage is recorded for the sprite); it resolves against declared iconsets first, then falls back to a `pack.name` against a compiled-in pack — so the built-in callout glyphs render with **no iconset declared**. This required threading `&IconRegistry` through the HTML-lowering path (`render_block` → `lower_html_block` → `render_html_variant` → `render_element_payload`, and `render_template`). Heading + body are escaped (the lower path doesn't run the inline engine). **Tilesets + tilemaps**: `@block("tileset")` names a spritesheet image plus its slice geometry (`source` path relative to the doc, `tile_width`/`tile_height`, optional `columns`/`margin`/`spacing` and `image_width`/`image_height`); `@children("tileset")` hangs off the document root like `iconset`. `@block("tilemap") extends SvgBlock` is a placeable, index-based tile grid for a `diagram`/`container`; like `icon`/`terminal` it's special-cased in Rust (`tileset.rs`), its WCL `lower` a stub (the SVG comes from an external image + crop math). The grid is authored numerically (`tiles: list<list<i64>>`, one inner list per row) or symbolically (`map: list<utf8>` of glyph rows resolved through `@children("tile")` `TileKey` legend entries — `tile "#" { index = 0 }`; `map` wins when both are present); an `empty` index (default `-1`) and any unmapped glyph draw nothing. Each non-empty cell renders as a nested `<svg>` whose `viewBox` windows into the shared spritesheet (no per-tile clip-path/data-URI), wrapped in one `<g class="wdoc-tilemap">`; `scale` sizes the display, and `image-rendering: pixelated` (the always-injected `TILEMAP_CSS`) is the default with `smooth = true` opting into browser smoothing. A `TilesetRegistry` (mirrors `IconRegistry`: `RefCell<BTreeSet>` of used names, carried inside `InlinePatterns`, reached via `patterns.tilesets()` and threaded alongside `icons` through `render_diagram`/`render_layout_children`/`render_shape`/`render_container`/grid+layered render *and collect* passes — the collect side gains the param so the tilemap's data-derived bbox feeds edges + viewBox fit, via `tilemap_bbox`) reads each sheet's pixel dimensions at load from the file header (a tiny no-dep PNG/JPEG/GIF reader in `image_dims`; explicit `image_width`/`image_height` override it, and an undetermined size is a `BuildError::Tileset`), records which tilesets a rendered tilemap uses, and after the page loop copies each used image verbatim into `_wdoc/tileset-<name>.<ext>` (deterministic, collision-free); `serve`'s `/_wdoc/` route content-types `png`/`jpg`/`gif`/`webp`/`bmp`. Like icons, tiles only resolve when **served/hosted** (the sheet is referenced by relative URL), not via `file://`. The example uses a vendored Kenney CC0 sheet (`examples/wdoc/assets/`); since the renderer never decodes pixels (only reads IHDR + copies bytes), tests feed a hand-crafted fake PNG. **Dopesheets (animated sprite sheets)**: `@block("dopesheet") extends SvgBlock` (`lib/dopesheet.wcl`, renderer `src/dopesheet.rs`) plays a range of frames out of a sprite sheet at a set `fps`. It names the sheet (`@inline(0) source`, like `image`) plus its frame geometry — `frame_width`/`frame_height`, `offset_x`/`offset_y` to the first frame, and origin-to-origin `stride_x`/`stride_y` (defaulting to the frame size) — and `columns` (default: fit from the sheet width), a `from`/`to` frame range (default: every frame), `fps` (12), `loop`/`autoplay`/`controls` (all true), `smooth`, and `scale`. Like `tilemap`/`image` it's special-cased in Rust (its WCL `lower` is a stub) and **reuses the `ImageRegistry`** — no new registry — to copy the sheet into `_wdoc/` and read its pixel dims; `render_dopesheet` emits one `<g class="wdoc-dopesheet">` carrying the geometry as `data-dope-*` attrs plus a nested `<svg class="dope-frame">` whose `viewBox` windows the `from` frame, over the full-sheet `<image>`, plus a centred `.dope-btn` play/pause glyph. The bundled `dopesheet-player.js` (written to `_wdoc/` + `<script defer>`-loaded once per page when `dopesheet::uses_dopesheet` is true anywhere, mirroring the terminal/map/pan-zoom player pattern) advances the inner `viewBox` frame-by-frame at `fps` via a rAF accumulator (frame `k` → flat index `from+k` → `(col,row)` → source rect), looping or stopping-at-end (replay glyph); clicking the group toggles play/pause. `dopesheet_bbox` (single frame × `scale`, via `tileset::place`) feeds the collect pass. Default styling is `stylesheet "wdoc-dopesheet"` (pixelated by default; `smooth = true` opts out). Like tilemaps, frames only resolve when **served/hosted**. The example uses a vendored CC0 spinning-coin sheet (`examples/wdoc/assets/pixel-coin.png`, truezipp). **Interactive diagrams (pan + zoom)**: a `diagram` with `pan_zoom = true` is wrapped in a `<div class="wdoc-diagram-viewport">` and gets overlaid +/−/⟲ controls; the renderer stamps the fitted view + limits onto the `<svg>` as `data-base-viewbox` / `data-zoom-min` / `data-zoom-max` (scale factors, 1.0 = fitted) / `data-pan-margin` (overscroll px). The bundled `diagram-pan-zoom.js` (mirrors the terminal-player asset pattern — written to `_wdoc/` and `<script defer>`-loaded once per page when `render::uses_pan_zoom` is true anywhere in the doc; it no-ops on pages without a viewport) drives the SVG `viewBox` as the camera: wheel zooms toward the cursor, drag pans (pointer events), buttons zoom about centre / reset. Zoom is clamped to `[zoom_min, zoom_max]`; pan, when zoomed in, allows half-a-viewport of overscroll past each content edge plus the author's `pan_margin`, and centres the content when zoomed out to (or past) the fitted view. Styling is `DIAGRAM_CSS` (always injected; controls paint with `currentColor`). Diagrams without `pan_zoom` keep the bare-`<svg>` output unchanged. **Page templates**: a `site` block sets a `default_template` (+ `title`); a page overrides it via its own `template = :name` field. **Start page**: a page may set `start = true` to become the page served when none is specified (`/` for the root site, `/<site>/` for a sub-site) — `build` copies it to the site's `index.html` (so no page need be literally named `index`); at most one `start` page per site (more is a `BuildError`), and with none a page named `index` is used, else `ensure_site_index` redirects to the first page. A `@block("template")` carries `render = fn(TemplateCtx) -> list<HtmlFundamental>`; the renderer builds the `TemplateCtx` (the page's rendered body as the `content` part, the site title, and the list of every page as `PageRef`s) and the returned fundamentals become the `<body>` (`render_page` still owns `<head>`/CSS). Templates compose structure with two general fundamentals — `Element { tag id? class? attrs? children }` (recursive) and `Raw { html }` (verbatim) — and build their nav from `ctx.pages` (every page, in source order) or `ctx.menu` (a curated navbar). **Navbar menu**: a `site` may declare a `menu { item "Label" { page = name? | href = url?  …nested items } }` block (recursive, mirroring the book's `toc`/`chapter`); the renderer reads it (`read_menu`/`menu_to_value` in `html.rs`, parallel to `read_toc`/`toc_to_value`) into `TemplateCtx.menu: list<MenuEntry>` — each entry resolves an `href` (internal `page`→`<page>.html` wins over an external raw `href`; empty for a parent/grouping item), a `current` flag, and nested `children` — and it's validated like the toc (`menu_missing_page` ⇒ build error on an unknown page). The `webpage` template renders it as a nested `<ul class="menu">` via a self-recursive `site_menu` + leaf `menu_entry` (dropdown parents are a `<button class="menu-toggle">` driven by a one-time inline click-toggle script appended only when a menu exists; CSS lives in `webpage_css`); with no `menu` it falls back to the flat per-page link list (byte-identical to before). "Parts" are just functions returning `list<HtmlFundamental>` that a template calls and embeds. Two stdlib templates ship: `webpage` (Hugo-style header + top nav from the site `menu`) and `book` (mdbook-style fixed left chapter sidebar with current-chapter highlight + reading column; the sidebar is a nested, ordered table of contents declared via a `toc { chapter "Title" { page = name?  …nested chapters } }` block inside `site` — recursive `chapter` entries nest to any depth, `page`-less chapters are grouping headings, and a `chapter` pointing at an unknown page is a build error); their default styling is injected via `SITE_CSS` / `BOOK_CSS`. No `site`/`template` ⇒ pages render bare (pre-template behaviour). **Colour themes**: `lib/theme.wcl` defines two single-variant unions — `Palette::Of { … }` (18 generic colour roles: `bg`/`bg_alt`/`bg_inset`/`overlay`/`border`/`fg`/`fg_muted`/`fg_subtle`/`heading`/`selection` + the eight hues `red`/`orange`/`yellow`/`green`/`cyan`/`blue`/`purple`/`pink`, which double as the chart cycle and the accent vocabulary) and `ColourTheme::Of { name dark light }` — plus seven built-in `let` bindings (`nord` / `gruvbox` / `solarized` / `catppuccin` / `tokyonight` / `kanagawa` / `everforest`), each with an official dark + light `Palette`. A `site` selects one by **value** via `theme = <ColourTheme>` (any built-in *or* a user's own `let mine = ColourTheme::Of { … }` — themes are ordinary values, referenced directly) and a hue via `accent = :blue` (one of the eight; default blue); an unset `theme` defaults to `nord`, and a document with no `site` block stays unthemed (byte-for-byte unchanged). The data lives in WCL but the CSS is emitted in Rust (`render/theme.rs::site_theme_css`, mirroring the other `*_CSS` constants — `let`-bound fns aren't reachable via `Document::call_function`/`get`, only field-value evaluation resolves them, so `build.rs` reads the site's `theme` field `Value`, or evaluates `nord` via `parse_expr`+`eval_expr` for the default, destructures the `Palette::Of` records, and formats CSS): four `:root` blocks set the `--wdoc-*` custom properties — the dark palette as the default, the light palette under `@media (prefers-color-scheme: light)` and on `:root[data-theme=…]` (the book toggle) — followed by mode-independent apply rules that paint `var(--wdoc-*)` onto body/`.wdoc-body`, `::selection`, links (`--wdoc-accent`), `.heading-1..6`, `pre.code-block` + the `.tok-*` syntax classes, `.wdoc-series-1..8`, `.callout.<type>` accents, and `.wdoc-table`. `site_css` splices this between the library and user `class` rules so the theme overrides built-in defaults (chart palette, token colours) while user `class` blocks still win; the `webpage`/`book` template CSS (body-embedded, so it would otherwise out-cascade the head theme) consumes the same vars via `var(--wdoc-border, …)` / `var(--wdoc-bg-alt, …)` fallbacks, so future templates theme for free just by referencing the vars. `serve` renders into a tempdir (or `--out`) by calling `build()`, watches the source dir via `notify` and rebuilds on every `.wcl` change; axum routes `/` and `/<name>[.html]` are static-file reads off that directory, plus `/_wdoc/<file>` (content-typed, path-traversal-guarded) for the bundled terminal font + player assets and the icon sprite. Build errors are logged to stderr; the last successful render keeps serving.
- `crates/wcl_lang/fuzz` — `cargo-fuzz` targets (parse + eval); run via `just fuzz-run <target>` on nightly
- `editors/vscode` — minimal VS Code extension stub that spawns `wcl lsp` for `.wcl` files
- `editors/tree-sitter-wcl` — tree-sitter grammar stub for editors that consume them
- `examples/` — fixture files used by tests (incl. `imports/` for module loading and `errors/` for negative diagnostics)

## What's implemented

- Hand-written lexer + recursive-descent parser → `Source` AST + `SymbolIndex`. String literals and heredocs (`<<TAG`) interpret escapes; the **raw** heredoc `<<'TAG'` (single-quoted opening tag, bare-tag closer) takes its body verbatim — no escapes, no `${…}` interpolation, indentation stripping unchanged — for backslash-heavy text (LaTeX, regexes, Windows paths). It yields a `StringLit::Utf8` like any heredoc, so the parser/AST are unaffected; the formatter re-emits a backslash-bearing utf8 value as `<<'TAG'` so round-trips stay valid.
- `Document` view layer with lazy, cached field evaluation and cycle detection
- Expression evaluator: literals, identifiers, member access, calls, function literals, let-bindings, block expressions, arithmetic / comparison / logical operators with implicit numeric promotion (`1 + 2.0`, `1u32 == 1i64`)
- `let` items: `let name = expr` at the file (global) scope or inside any block. Composition helpers (values or functions) that resolve by name in sibling/descendant expressions but are **not** document data — invisible to `Document::fields`/`blocks`, `get`, JSON, and schema validation (not registered in the symbol index). Lexically scoped (inner shadows outer), lazily evaluated, cycle-detected. Distinct from the expression-level `let … ;` inside `{ }` block expressions; item form takes no terminator.
- Schema system: `@document`, `@schemaless`, `@block`, `@child`, `@children`, `@inline`, `@default`, `@table`, `@decorator`; structural validation via `Document::schema_errors()` / `SchemaViolationKind`
- Type system: `type`, `interface` (with `extends`), `union` (record / typeref / unit variants), `symbol_set`, builtin numeric + string variants, `list<T>`, `tensor<T, [...]>`, `fn(...) -> T`, named refs, `&T` reference fields with scope-aware lookup
- Host bindings: `Environment` registers synthetic types + builtin functions via `from_fn` (`FromValue` / `IntoValue` traits); each `BuiltinFn` can carry a printable signature
- Host-callable functions: `Document::call_function(name, &[Value])` looks up a top-level binding and invokes it; `Document::call_value(&FnValue, &[Value])` runs an already-resolved function value. Both use a fresh evaluation context rooted at the document. Pairs with expression-form variant construction (`Union::Variant { field: expr, ... }`) so hosts can ship interpreters over user-supplied lowering functions. Local-bound records/variants participate in member-access (`p.x` works for a record-typed parameter).
- Builtins: collections (`map`/`filter`/`fold`/`len`/`sum`/`range`/`head`/`tail`/`flatten`/`zip`), tensors (`tensor`/`tensor_data`/`tensor_shape`/`tensor_reshape`), strings (`split`/`join`/`replace`/`contains`/`starts_with`/`ends_with`/`to_upper`/`to_lower`/`trim`), lists (`list_contains`/`reverse`/`sort`/`unique`/`index_of`/`take`/`drop`/`at`), math/geometry (`sin`/`cos`/`tan`/`asin`/`acos`/`atan`/`atan2`/`radians`/`degrees`/`sqrt`/`cbrt`/`pow`/`hypot`/`exp`/`ln`/`log10`/`log2`/`floor`/`ceil`/`round`/`trunc`/`abs`/`sign`/`min`/`max`/`clamp` + `pi`/`tau`/`e` constants — all work in `f64`, widening integer args, registered in `math.rs`), control flow (`error`/`panic`/`assert`/`format`/`concat`)
- Imports: eager top-level `import`; lazy `import` inside blocks. Two forms: quoted `import "./x.wcl"` (disk, resolved relative to the importer + canonicalised) and angle-bracket `import <pkg/x.wcl>` (system) — resolved through a `wcl_lang::Registry` of binary-embedded files via `registry.loader(fallback)` (built on the `FileLoader` alias; system paths route under the `SYSTEM_IMPORT_ROOT` sentinel, importer-relative within the registry namespace). Imported declarations participate in the importer's structural validation (`validate_document` takes the imports' symbol indexes) and in `resolve_path`/`type_decl`/`connection_decl`/`blocks()` (all walk `all_sources()`); `Document::blocks_with_source()` tags each block with its origin file (`None` = root) so hosts can order imported-vs-root output (e.g. CSS cascade)
- Edit path: `parse_for_edit` + AST mutation + `format::to_source` round-trip, driving `wcl set` and `wcl fmt`. `format::FormatConfig` exposes indent / trailing-comma / blank-line cap; `wcl fmt --indent` / `--no-trailing-comma` surface them at the CLI.
- Interactive REPL (`wcl repl [<file>]`) — plain stdin loop with multiline continuation; tagged parse vs eval errors; `:quit` exits
- JSON value serialization — custom one-way `Serialize` on `Value` emits idiomatic JSON (scalars as primitives, lists as arrays, records as objects, variants as `"Name"` / `{"Name": payload}`); `wcl get --json` uses it. `TypeRef`/`Span`/`BuiltinType` still round-trip via derive.
- LSP server (`wcl lsp` / `wcl lsp --tcp ADDR` / `wcl lsp --log <path>`): diagnostics, formatting, document symbols, go-to-definition + cross-file, find-references + cross-file, hover, completion (trigger-driven and identifier-position with locals + builtins), semantic tokens incl. inside `${...}` interpolation slots, code actions (quick-fixes for unknown-field and disallowed-child schema violations), incremental text sync via `ropey`, multi-connection TCP listener. **Root document**: on `initialize`, the server picks up `initializationOptions.root` (or falls back to `<workspace>/main.wcl`) and resolves every cross-file lookup through it. Open editor buffers shadow disk contents via an overlay [`FileLoader`] (`wcl_lang::overlay_loader`), so unsaved edits in any imported file participate in the root parse.
- LSP integration tests (`crates/wcl_lsp/tests/server.rs`) drive `Backend`'s `LanguageServer` trait directly through `tower-lsp`
- Fuzz harness in `crates/wcl_lang/fuzz/` with `parse`, `eval`, and `format_round_trip` targets, seeded from `examples/`. CI runs a 30 s `parse` smoke on every push.
- Editor stubs in `editors/` — VS Code extension that spawns `wcl lsp`, tree-sitter grammar for highlighting

## Conventions

- Hand-written lexer + recursive-descent parser. No nom, no parser generators.
- Diagnostics use `miette` + `thiserror`. Every parse error carries a `Span` and a `NamedSource` so the CLI can render snippets.
- Keep the dependency list minimal. Add a new crate only when it earns its place.
